# 云部署方案对比

## 方案一：GitHub Actions（推荐 · 免费）

**费用**：¥0/月（GitHub 免费额度足够）

**原理**：
- 把代码推到 GitHub 私有仓库
- 用 GitHub Actions 的 schedule 触发器每天早上 8:30（北京时间）跑
- 每次运行：装依赖 → 抓投中网 → 抓行情 → 抓推文 → 生成报告 → 发 Telegram

**优点**：
- ✅ 完全免费
- ✅ 不需要管服务器
- ✅ 不用关电脑
- ✅ 支持定时任务（cron 表达式）

**缺点**：
- ❌ GitHub Actions 的 schedule 可能延迟 5-30 分钟（非实时）
- ❌ 每次运行需要安装 playwright chromium（约 2 分钟）
- ❌ 需要申请推特的 API Key 放到 GitHub Secrets 里

**流程**：
```
代码 push 到 GitHub
       ↓
每天 UTC 0:30（北京时间 8:30）触发
       ↓
GitHub Runner 启动 Linux 容器
       ↓
安装依赖 + playwright chromium
       ↓
抓投中网文章 + 行情 + 推特
       ↓
生成报告 → 发到 Telegram
       ↓
容器销毁，不留痕迹
```

## 方案二：阿里云轻量服务器（最稳）

**费用**：¥34/月（香港节点 ¥24/月）

**原理**：买一台最低配云服务器，装好 Python + Playwright，把当前项目整个传上去，设置 crontab

**优点**：
- ✅ 和当前 Mac 上一模一样
- ✅ 24 小时在线，无延迟
- ✅ 可以同时跑其他脚本

**缺点**：
- ❌ 要花钱（¥24-34/月）
- ❌ 需要简单配置服务器环境
- ❌ 需要续费管理

---

## 推荐选择

| 因素 | GitHub Actions | 云服务器 |
|------|---------------|---------|
| 费用 | **¥0** | ¥24-34/月 |
| 时效性 | 可能延迟 5-30 分钟 | 准点 |
| 部署难度 | 需把代码推 GitHub + 配 Secrets | 需买服务器 + 装环境 |
| 长期维护 | 几乎零维护 | 需续费 + 偶尔更新 |

**建议**：先用 GitHub Actions（免费），如果觉得延迟不可接受再切云服务器。
